RoCE 平台学习导览

这是一张地图,不是教材:按"哪个集成阶段需要先会什么"组织四条学习轨道,每项只回答三件事——学什么、为什么此刻学、动手做什么——然后把你送到正确的深读入口:《VCU118 RoCE 平台集成手册》对应章节、仓库源码路径、或你自己的 Obsidian 协议笔记。

第一周怎么走(单人推荐序)
  1. T2-1 起手:把 rocev2 csim 环境搭起来(边搭边补 HLS 概念)——这同时就是集成手册的 Stage A;
  2. 等综合/仿真跑的间隙读 T1(协议三件:帧格式 → PSN/ACK → WRITE 分段);
  3. csim 通了之后进 T3(代码结构),按数据流顺序读,别按目录顺序读;
  4. T4(Corundum)推迟到 Stage C 后半段再开——太早读记不住。

T1

RoCE v2 协议

解锁 Stage B

T1-1帧格式:Eth/IP/UDP:4791/BTH/RETH + ICRC

学什么一个 RoCE v2 包每一层的字段与取值;ICRC 的"不变量"规则(哪些字段被掩码后参与 CRC)。 为什么Stage B 的核心工作就是逐字段校验 m_axis_tx 输出帧;ICRC 错 = 静默丢包,是全平台最阴的故障模式。 动手用 Wireshark 打开任一 RoCE v2 抓包(或 Stage B 产出的 golden pcap),手工核对 BTH 的 opcode/PSN/destQP 与 RETH 的 vaddr/rkey/DMALen;再手算一帧 ICRC 与工具比对。 入口手册 §2.1 帧格式 · 源码 hdl/common/icrc.sv, hls/crc/ · Obsidian 003互联基础设施/rdma(ib_pack.h 逐字段笔记)

T1-2RC 状态机:PSN / ACK / NAK / go-back-N

学什么PSN 逐包递增与接收侧严格按序校验;ACK 累积确认与 AETH/MSN;NAK 触发条件与 go-back-N 重传;ACK 时钟化信用流控。 为什么Stage B 的负测试(跳 PSN → NAK)和 Stage E 的"一丢即挂"现象都由它解释;将来 dual-length 研究段改的就是这套记账。 动手在 myDevbox 上起 Soft-RoCE(rxe)+ tcpdump,发一个跨 PMTU 的 ib_write,观察真实 FIRST/MIDDLE/LAST 序列与 ACK 的 PSN/MSN 演进。 入口手册 §2.2 RC 语义 · 源码 hls/ib_transport_protocol/(状态机本体)· Obsidian rxe 笔记(内核参考实现)

T1-3WRITE 解剖 × PMTU 分段 × WRITE_WITH_IMM

学什么WRITE_ONLY / FIRST-MIDDLE-LAST 的 opcode 序列;FIRST/MIDDLE 严格 = PMTU(本栈 4096);RETH 只在首包;普通 WRITE 无响应端 CQE,WITH_IMM 才有。 为什么Stage B 通过标准里"≥PMTU 多包切分正确"就是它;WITH_IMM 是未来对 stock 网卡做压缩实验的接收通知设计,要从第一天留口。 动手拿 12KB 消息手画包序列(含每包长度与 PSN),再与 Stage B 仿真输出对照;找出 len 恰为 n×4096 时的边界情况。 入口手册 §2.3 WRITE 解剖 · hls/fns_config.hpp(PMTU 常量)
T2

Vitis HLS 流程

解锁 Stage A

T2-1HLS 工程三件套:csim → cosim → export,与 dataflow/接口 pragma

学什么csim(C 级功能验证)/ cosim(RTL 联合仿真)/ export(打包成 IP)的分工;DATAFLOW 进程流水;ap_ctrl_none 自由运行核与纯 AXI4-Stream 口意味着什么。 为什么rocev2 是 HLS 核,Stage A 全程在这套流程里;将来的 DCL gzip CU(gzip_compress_multicore_stream.cpp)也是 ap_ctrl_none 纯流式——同一套心智模型。 动手把 hls/rocev2 的 csim 跑通(= Stage A 的操作 1–2),记录 2025.2 与 2022.2 的行为差异进决策日志。 入口手册 Stage A · hls/rocev2/CMakeLists.txt + make.tcl.in(仓库自带构建流程,以它为准)

T2-2自带仿真基建:newFakeDram 与 simSwitch

学什么仓库自带的假 DRAM 模型与模拟交换如何把"内存侧 + 网络侧"都在 csim 里闭环——这是不上板做全协议仿真的关键。 为什么Stage A/B 的测例都构建在它们之上;读懂它们 = 知道 csim 的可信边界在哪(哪些行为是模型的,哪些是核的)。 动手在 csim 里发一个单 WRITE,dump 输出帧字节并与 §2.1 表逐项核对(= Stage A 通过标准)。 入口hls/rocev2/newFakeDram.hpp, simSwitch.hpp · 手册 §3.1
T3

fns 代码结构

解锁 Stage B / C

T3-1rocev2.cpp 顶层:按数据流读,不按目录读

学什么HLS 顶层的 dataflow 进程连线:入包解析 → 传输状态机 → 内存命令生成 → 出包组装;各 hls::stream 的语义。 为什么Stage B 的 testbench 要在正确的位置观察/注入;将来 codec 与 dual-length 的改动点也要在这张图上标。 动手读完画一张数据流图(进程 × stream 连线),标出:PSN 在哪生成、ICRC 在哪插入、RETH 在哪组装——三处坐标以后反复要用。 入口hls/rocev2/rocev2.cpp .hpp · 手册 §3.1 导读表

T3-2ib_transport_protocol:传输状态机本体

学什么opcode 序列生成/校验、PSN 记账、AETH 组装的具体实现;RETRANS_RETRY_CNT、RDMA_DEFAULT_PORT 等常量;RETRANS_EN 注释掉意味着哪些代码路径失活。 为什么这是"协议正确性"所在地,Stage B 负测试的预期行为要从这里读出来,不能猜。 动手从源码回答三问:收到重复 PSN 的包,代码走哪条路?NAK 在哪生成?无重传模式下 NAK 之后发起侧的状态是什么(→ 解释"一丢即挂")? 入口hls/ib_transport_protocol/ · 手册 §6 雷 #2

T3-3roce_stack.sv 包装层:集成边界与位域打包

学什么SV 顶层每个口的语义(SQ 推入/ack/内存命令/QP 配置/计数器);VITIS_HLS 与非 VITIS 两种 SQ 位域布局的差异(qpn 从 bit 32 起!)。 为什么Stage C 的 doorbell 垫片直接对着它写;位域打包错是 Stage C 故障表第一名。 动手照 §8 速查表写一个打包函数 + assert 自检(TB 里跑),再接 FIFO。 入口hdl/common/roce_stack.sv · 手册 §8.1–8.3

T3-4L2/L3 胶水:ipv4 / udp / arp_server / mac_ip_encode

学什么封装链路上 IP/UDP 头在哪组装、ARP 应答与静态 MAC 的两种做法;为什么反向可达(ACK 回程)必须双向配置。 为什么Stage C/D 的"帧发得出去但 ACK 回不来 → 无限重传假死"这类故障全在这层。 动手决定环回阶段的方案(建议:静态 MAC/IP 表,跳过 arp_server)并在 TB 里验证 TX/RX 双向帧头正确。 入口hls/{ipv4,udp,arp_server,mac_ip_encode} · 手册 Stage C
T4

Corundum 内部

解锁 Stage D / E

T4-1mqnic 数据面架构与 app_block 挂点

学什么Corundum 的 TX/RX 数据面分层;app_block 三层流接口(direct/sync/if)各在哪个位置截获;APP_AXIS_SYNC_ENABLE 等构建参数;s_axil_app_ctrl 的地址空间。 为什么Stage D 的全部集成动作都发生在 app_block 里;流口位置选错(direct vs sync)会白做。 动手读 mqnic_app_block 文档 + 端口表,写一页纸集成说明:我们的注入 mux、RX 过滤器、AXI-Lite 空间各接哪根线、开哪些参数。 入口Corundum docs/source/modules/mqnic_app_block.rst · 手册 §3.2 + §8.4

T4-2Corundum 仿真框架(cocotb)与 VCU118 工程

学什么fpga_100g 工程结构、testbench 组织方式、如何把自定义 app_block 挂进现有仿真;rev100 bitstream 的构建复现路径。 为什么Stage D 的通过标准要求"Corundum testbench 框架里 WRITE 环回帧不变形"——不重造仿真环境,借它现成的。 动手先原样重建一次 rev100(验证工程可复现),再跑一次 Corundum 自带 testbench 认识输出格式。 入口fpga/mqnic/VCU118/fpga_100g/(Corundum 仓库)· 手册 Stage D

T4-3JTAG-to-AXI · hw_server 与板级排障路径(无 PCIe)

学什么Xilinx jtag_axi Master IP + Vivado run_hw_axi(create_hw_axi_txn / run_hw_axi)如何驱动/读回 AXI-Lite 寄存器,零驱动零 PCIe;CMAC 状态/统计寄存器读法;"链路层 → MAC 层 → 栈入口 → ICRC → PSN"的二分排障法(每层有计数器)。 为什么当前板不插 PCIe 槽、仅 JTAG 连电脑(用户约束 07-16),敲 doorbell/写 WQE/读计数器全走 run_hw_axi;这条链路是 Stage E 唯一的 host 触达方式。 动手DAC 未到前就完成:台面供电 + JTAG(USB)+ hw_server 通、刷写、run_hw_axi 读一个已知常量寄存器自检、再读五个调试计数器(应全 0)——把 Stage E 的"前置"清掉。不碰 PCIe/驱动/BAR(那是 §7 的后续流程)。 入口手册 Stage E · §6 雷 #5/#8 · Xilinx PG174(JTAG-to-AXI Master)
