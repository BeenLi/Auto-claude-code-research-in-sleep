§1回答什么问题

  1. 载体怎么选? 台架无 PCIe 插槽。Corundum rev100 原样复用(a)与裸 CMAC 最小 shell(b),哪条在"无插槽 + JTAG 驱动"约束下是活路?要源码级证据,不要印象。
  2. 载体胶水会不会改变行为? Stage C 的验证是单时钟理想环境;真载体是三个异步时钟域(250MHz 核心 / ~322MHz CMAC TX / ~322MHz CMAC RX,且 RX 是 CDR 恢复时钟与 TX 不同源)+ 不可反压的 CMAC RX + 帧过滤。golden 传递性第四级:同签名输入,CMAC 侧捕获的帧必须仍与 Stage B/C 认证 golden 逐字节一致。
  3. 综合布线的裁决。 Stage B 的 HLS 报告估计协议栈 Fmax 只有 151.9MHz(目标 250);URAM 双口 + 字节使能推断从未过综合;资源表是未来论文的第一行数据。三者都只有布线后的数字算数。

§2原理

rev100 的三层锁:时钟根、复位根、控制根全押 PCIe

载体侦察(11 agents,逐条 file:line 验证)证明 rev100 不插槽是死芯片,且死因分三层:①时钟根 —— fpga_core 的 250MHz 主时钟就是 PCIe 硬核 user_clk(fpga.v:754→1689),其唯一时钟源是插槽金手指上的 100MHz 参考时钟(AL9/AL8,板上无振荡器,board 文件部件名就叫 pcie_8lane_edge)——物理缺失,无 RTL 可救;②复位根 —— mmcm_rst = pcie_user_reset(fpga.v:306),而复位同步器初值 1、挂在死的 user_clk 上,于是板上明明自由运行的 125MHz 振荡器与 Si570 的下游闸门被永久扣死:MMCM 不出钟 → CMAC bring-up FSM(跑 125MHz)不启动 → GT QPLL 不锁 → DDR4 复位恒 1——这层是 RTL 布线决策,可手术;③控制根 —— CMAC 数据阀门 ctl_tx/rx_enable 与 mqnic 端口寄存器相与,上电 0,唯一写路径是 PCIe BAR 的 AXIL 桥;且已建 bitstream 为 APP_ENABLE=0,app block 在综合期就被 generate 裁掉,bitstream 不可 patch。

裸 shell 的原则:只搬运被验证过的器官

cmac_gty_wrapper 自带 GT bring-up 状态机、默认全开的使能寄存器、cmac_pad(以太网最小帧填充)——且其时序约束 tcl 按 ORIG_REF_NAME 匹配,整体搬运不失效。shell 只做两处再扎根:mmcm_rst=1'b0、MMCM 加 CLKOUT1=250MHz;控制主换成 jtag_axi(JTAG 线缆即"我们的 PCIe");阀门直接拉高。Corundum 源码一行不改,全部手术在自己 ~470 行顶层里。

golden 判据升级:按流,不按捕获文件

Stage C 的 RX-direct 环回 RTT 极短,首段 ACK 会插在两个 WRITE 分段之间;Stage D 的真 CDC×2+过滤器路径 RTT 变长,ACK 排到分段之后(板上亦然)。单一捕获流的交错次序是 RTT 依赖的,不属于协议契约;契约是每条流内部的字节序列。判据升级为:WRITE 帧子序列与 ACK 帧子序列各自逐字节等于认证 golden(check_stage_d_golden.py);c_write64(单帧单 ACK)仍整文件逐字节一致,ICRC ccbeb072 不变。

综合器是另一位评审者

xsim 对两类东西宽容而综合器严格:SV 语法混进 .v 文件(照吃)、RAM 访问模式(照仿)。因此"仿真全绿"不等于"可综合",每一次综合失败都是一条免费的静态审查——本阶段五次尝试各抓到一颗真雷(§4),全部回灌成代码修复 + 回归门。

一个包的一生

一 · 主机侧:三次写,一次敲

  1. 1送料 —— Mac 通过一根 USB 调试线(JTAG),把要发的数据字节写进板上的暂存内存(片上 SRAM 256 KiB,窗口地址 0x800000 起,32 位一拍 + 字节使能)。全程无 PCIe、无驱动、不碰主机内存。
  2. 2报到 —— 写连接配置寄存器:这条专线本端是谁、对端是谁、对方内存的钥匙是什么;写 SUBMIT 拍一张快照,推进硬件的连接表与 QP 表。
  3. 3下工单 ＋ 敲门铃 —— 把这一单的五件事填进寄存器(走哪条连接 / 数据在本地哪 / 写到对方哪 / 多长 / 是不是末段),最后写一下 0x70 这个门铃。硬件从这一拍起自己干活。(忙时敲门会被静默忽略,软件先轮询 STATUS.busy;工单里的 opcode 字段只是登记项,实际段类型由下一步的切分 FSM 决定。)

二 · 前端:拆成段,主动喂数据

  1. 4切段 —— 一个包最多装 4096 字节,超了就切成 首段/中段/末段,每段变成一条内部命令推给协议引擎。(本版没有"排队列 ＋ 硬件自己去主机内存取工单"那一套:工单就是寄存器,门铃一响直接开工。)
  2. 5喂料 —— 命令和数据是两条独立的路。先推该段命令,命令被接受后,才从暂存内存按本地地址把这一段的数据整段推给引擎,然后才轮到下一段。引擎不会自己来取——它其实也发了取数命令,但被前面那个分流器拦下了,数据一律由前端主动喂。
  3. 6限流放行 —— 发送窗口给每段发一个槽号,最多允许 16 段同时在飞,满了就等对方确认回来再放下一段。(本版一次只在飞一个工单,这个窗口远用不满。)

三 · 协议引擎:装信封

  1. 7复制存底(本版已禁用) —— 正常设计里每一拍数据都复制一份进重传缓冲,万一丢包好重发。Stage D 把这一路接死成常量:存底的那一份写进虚空(端口恒 ready,不拖慢发送),既不存底、也不会重发。
  2. 8逐层加头 —— 像寄快递,两条路并行走。头部面:先写收件地址(只有首段有,告诉对方写到哪个地址、多长),再给整个包分配包序号(收方靠它判断丢没丢、乱没乱)。载荷面:同时把这一段载荷按 4096 字节取齐,拼上刚造好的那层头。两条路在最后一站合流,贴上运单号,再装进 UDP 信封(门牌号固定 4791)、最后装进 IP 信封。
  3. 9封口出栈 —— 帧尾追加 4 字节校验和(RDMA 自带的那一层 ICRC,和以太网的 FCS 不是一回事),整帧从引擎出口发出:一拍 64 字节,250 MHz。

四 · 上线:换时钟,上铜缆

  1. 10上线 —— 帧过一个异步缓冲,从 250 MHz 跨到发送时钟域(~322.27 MHz)。随后进 cmac_gty_wrapper:每帧都经过补零模块,但只有不足 60 字节的帧会被真补——本平台只有 48 字节的 ACK 落进这一档,124 B 与 4156 B 的帧原样通过。再交给 CMAC 硬核与 GTY 串行化,从 QSFP1 出去,经一根 DAC 铜缆绕回同一块板的 QSFP2。

五 · 接收:拆信封、落地、销单

  1. 11进门与安检 —— 收方的 MAC 不能被喊停,所以先过一个"满了就丢"的缓冲跨回 250 MHz;再由过滤器在第一拍一次判完三个条件——IP 版本、protocol、目的端口 4791,三条全中才放行。引擎逐层拆掉 IP／UDP 信封、拆头,按包序号检查有没有乱序或重复,序号对的才放行。(本版不校验那 4 字节 ICRC——校验分支在代码里被关掉了,B5。)
  2. 12落地与销单 —— 引擎先发一条放置描述符(写到哪、多长),数据随后落进暂存内存——这就是 RDMA 的"绕开 CPU 直接落地"。同时响应方逐包生成 48 字节确认帧(8K 消息回 2 个、12K 回 3 个),以最高优先级插队发出。注意确认帧不走"回程":本设计只有一条发送线和一条接收线,确认帧与数据同向,一样从 QSFP1 出、QSFP2 进——请求方和响应方本来就是同一片 FPGA 上的同一个协议栈实例,铜缆只是把它自己的帧递回给自己。中间段的确认只用来释放窗口槽,只有末段确认才产生一条完成通知;主机读一下计数器 / LAST_ACK 寄存器,就看见"这单干完了"。
岔路(仅本版)因为第 ⑦ 步被禁用,链路上真丢一帧,发送方会永远等不到确认:重传计数器非零、发送永久停摆,唯一出路是复位(D8)。所以 Stage D 的全部结论都建立在"链路零丢帧"之上。引擎内的重传定时器仍在跑,但重放数据无处可读;请求方定时重传(B9)在本 bitstream 上不可观测。
那以太网 / MAC 层呢?标准 RoCE v2 要,本平台没有。我们的帧第一个字节就是 IP 头的 0x45,线上一个二层字节都没有——负责造那 14 字节以太网头(目的 MAC / 源 MAC / EtherType)的那一站被整体省掉了。
为什么这样也能通:铜缆把本板的两个口点对点直连,两端是同一片 FPGA 上的同一个协议栈,没有交换机要转发、没有第二台机器要认 MAC、也没人会发 ARP 查询,这 14 字节的三项功能全部空转。
但 MAC 层并非不存在:CMAC 硬核仍在,它把我们交给它的字节原封不动发上线(前导/SFD/FCS 等硬核内部行为本仓无配置记载,本报告不作断言)。实证:两端 CMAC 对这种无二层头的帧照收照发——Stage E 板上 tx_frm = rx_frm = 2,落地数据逐字节 bit-exact。
代价记在账上:真要跟 ConnectX-5 互通,必须在 CMAC 前后插回 fns 的 mac_ip_encode / ip_handler,届时每帧多 14 字节,抓包口径与整条校验链都要重定——所以 07-23 的决策是到 CX-5 互操作站再插装,Stage D 保持认证态不动。

§5结果怎么看

读法:协议栈 + 载体 + 调试全链约占芯片 7%,>88% 余量给未来的 transform 引擎、gate 电路与 Vitis DCL deflate CU——资源不是本平台的约束。BRAM 回退版(尝试 4)数字:LUT 7.30% / FF 5.97% / BRAM 5.86%(staging 占 64 块)/ URAM 0。

golden 传递性(第四级)

§6发现与边界

D1rev100 三层锁(时钟/复位/控制)—— 载体决策的证据基座。

见 §2。要点:PCIe refclk 物理缺失不可手术;复位树把自由运行振荡器的下游全扣死(可手术);数据阀门唯一主人是 PCIe BAR;APP_ENABLE=0 的 bitstream 不可 patch。决策 (b) 裸 shell,Corundum 一行不改。

D2帧格式:roce_stack 收发 IPv4-first 裸帧,无以太网头。

golden 实测 byte0=0x45、byte9=proto、bytes22-23=dport。环回台架两端都是本栈,自洽;CX-5 互通必须补以太网 encap/decap(已加入 interop 检查单)。评审 D-R1 的以太网偏移过滤器若上板,将丢弃 100% 流量且 TB 假绿——首跑前评审的直接回报。

D3cmac_pad 填充裁决:栈容忍 60B 填充 ACK。

板上每帧过 cmac_pad(首拍 tkeep 补至 60B、pad 零填)。TB 建模后 CQE 正常关闭:fns RX 各级按头部长度字段切分、AETH 定偏移解析,pad 字节落在 ICRC 之后不被检查(RX ICRC 检查本分支编译剔除,Stage B B5)。仿真-板级分歧点提前消解。

D4捕获流交错次序是 RTT 的函数,golden 判据升级为按流。

协议契约在流内不在流间。判据脚本 check_stage_d_golden.py 按 ACK 签名(单拍 48B)分类后逐字节比对。Stage E 板上捕获同理。

D5xsim 宽容 ≠ 可综合:两类免费静态审查。

①SV 语法混 .v(17 个 HLS 零初始化补丁);②RAM 访问模式(动态位段基址)。教训:凡手工补丁进 HLS 生成文件,须以最严格方言书写并 translate_off 护住。

D6字节使能 TDP 无法推断进 URAM(2025.2 实测),XPM 直驱是正路。

read-first 与 no_change 两形态均触发 8-12186("invalid write mode" 文案误导——真因是 BWE+TDP 组合),静默回退 64 BRAM。xpm_memory_tdpram(ultra/BWE8/no_change/latency-1)直接例化 URAM288;行为与原语义逐点吻合(九项回归 + 不变性全绿),零初始化由 MEMORY_INIT_PARAM="0" 顶替 SIM_ZERO_INIT。BRAM 回退版整套报告留档(out_attempt4_bramfallback/)。

D7FWFT stub 改写:仿真 stub 也要按可综合写。

Stage B 的组合读 FIFO stub 综合成 512×577 分布式 LUTRAM(数十万 LUT 位)。改写为 BRAM 同步读 FWFT(+1 拍 empty→valid,消费者全弹性)后,16 项字节级不变性证明无害。sim/synth 双侧标记护栏防新旧混用。

D8运维边界:retrans 楔死特征 + doorbell 前置条件。

retrans mem 口绑死 ⇒ 板上任何真实丢帧(误码/FIFO 满)= CNT_RETRANS≠0 且 TX 永久停摆,唯一恢复是复位。RTL 不把 doorbell 挡在链路对齐前 ⇒ LED5/6(rx_aligned)常绿才准敲 doorbell;链路状态可读寄存器位列为 Stage E 准备项。B9(请求方定时重传)仍 OPEN——环回 ACK 即时返回,此处测不到。

边界:CMAC/GT/jtag_axi 硬核不在行为仿真(Stage E 板上验证);L0 逐条敲门测不了吞吐(手册既有边界);Vivado 报 1 条 eval-license 样板 CRITICAL WARNING(同一 license 建出过可用 rev100 bitstream,不阻塞);寄存器映射 0x00-0xB0 + staging 窗口 0x800000 与 Stage C 完全一致(STAGE_C_REPORT 的驱动文档继续有效)。

§7结论与移交

结论载体 (b) 裸 CMAC shell 成立且已落地:roce_l0_top + 载体胶水在真异步时钟下行为不变(golden 四级传递),250MHz 布线收敛(WNS +0.072~+0.119ns),资源占用 ~7%,bitstream 已产出。Fmax 151.9 悬案(过悲观)与 URAM 推断问题(不可推断,XPM 直驱)双双了结。
