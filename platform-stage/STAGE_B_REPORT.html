§2实验原理

2.1 RTL 仿真验证什么、不验证什么

csim 跑的是 C++ 函数,流是无限深队列、没有时钟;RTL 仿真跑的是综合后的门级前身(周期级握手、有限深 FIFO、真实的 BRAM 初始化行为)。所以 Stage B 能新回答:反压与握手是否正确、上电初值是否安全、跨模块位域是否对齐、ICRC 电路的输出值。它仍然回答不了:时序能否收敛(那要 post-route,Stage D)、真实 Xilinx FIFO IP 的行为细节(本实验用行为替身,见 §6 边界)。

2.2 对拍方法学:csim golden 是唯一裁判

Stage A 的单 WRITE 帧(签名值激励)是被逐字段验证过的 golden。Stage B 的判据设计成一条不等式:RTL 帧的前 120 字节必须与 csim golden 逐字节相等,且 keep 恰好多出 4 个有效字节——多出的正是 csim 不物化的 ICRC。任何偏差要么是包装层的缝(如 laddr/raddr 互换,§6-B2),要么是 RTL 化引入的错。这样 Stage A 的全部验证成果被直接继承,Stage B 只需为"增量"负责。

2.3 ICRC 的"独立双算"

ICRC 的正确性不能靠"电路自己说了算"。我们写了一个与硬件毫无共同血统的参考实现:Python + zlib 的 CRC32(同一多项式 0x04C11DB7 反射式),按 IBTA 附录规则对帧做掩码(IPv4 的 DSCP/ECN、TTL、头校验和,UDP 校验和,BTH resv8a 全部置 1,前缀 64 位全 1),小端序发射。SV 的 icrc.sv(961 行流水线 CRC512)和 30 行 Python 得出同一个 32 位值,才算数。签名值方法在这里复用:换一个 RETH VA,两边的 ICRC 必须一起变。

2.4 回灌闭环:Stage E 的仿真彩排

单板环回(QSFP0═DAC═QSFP1)的本质是"自己的 TX 是自己的 RX"。Stage B 在仿真里预演它:把捕获的 TX 帧原样喂进 s_axis_rx。由于 QP 表里 remote_psn 与 local_psn 配了同一初值,DUT 会以响应方身份接受这帧——放置命令、放置数据、回 ACK 全部可观测;再把 ACK 帧喂回去,请求方的 CQE 类比信号(m_rdma_ack)和流控释放也闭环。

2.5 负测试按 RETRANS_EN=开 设计

Stage A 勘误确认本分支重传逻辑默认开。所以负测试的预期不是"丢弃",而是重传协议的标准反应:重复 PSN → 不重放数据、重发 ACK;PSN 跳变 → NAK(PSN Sequence Error,AETH syndrome 0x60)并携带期望 PSN。PSN 跳变帧的 ICRC 由 Python 参考实现重算后经 plusarg 注入——参考实现在这里第二次发挥作用:它能构造电路自己造不出来的"合法坏帧"。

3.2 DUT 内部架构与三条数据流

发送流(橙,左→右):TB 先写 QP/conn 配置(灰箭头,一次性);SQ 命令(dreq_t)进 rdma_flow 做流控放行,放行后按位打包成 HLS 的 txMeta 喂给 rocev2——发现 B2(laddr/raddr 互换)出在这一步打包,B6(BRAM 读 X 死锁)出在 rdma_flow 内部的指针表。与此同时 payload 必须由用户侧主动推进 mux_retrans(B3:引擎对 WRITE 也发内部取数命令,但 mux 吞掉不透传,m_rdma_rd_req 只在 READ 响应时跳);mux 把每一拍数据一分为二:一路给 rocev2 打包,一路进重传缓冲(灰虚线),两路 tready 取 AND、锁步前进。裸帧经 trimmer、icrc(追加 4B)从 m_axis_tx 出去,TB 逐拍捕获,即 B-4/B-5 判据的对拍对象。重传缓冲按 {vfid,pid,offs} 分槽、每槽一个 PMTU——这给 B4(SQ 生产者必须预切分)补了电路层理由:超 PMTU 的命令会溢出自己的槽。

接收流(青,右→左):右侧灰虚线即"回灌"——TB 把捕获的 TX 帧原样喂回 s_axis_rx,是 Stage E 板上 DAC 环回的仿真等价物。帧经 FIFO 行为替身(B7 案发地:xsim 不重算引用 SV 队列方法的连续赋值)与 ack_gap_enforcer 进入 rocev2,以响应方身份解 RETH、发放置命令+数据(m_rdma_wr_req/m_axis_rdma_wr,TB 验证 vaddr/len/payload 位精确);ACK 信息经 rocev2 → rdma_flow 入 CQ,以 32 位 ack_t(B8,last 门控)从 m_rdma_ack 读出,完成 CQE 闭环。

两处如实的画法:RX 通路上没有 ICRC 检查站——本应在 rocev2 入口做的校验被 crc.hpp:39 分支级禁用(B5),故图中无此站;rx FIFO 虽在包装层内部却画成虚线框,因为 10 个 Vivado FIFO IP 本实验全部用行为替身顶替(§6.2 边界第二条)。B2/B3/B4 三条契约缝全部位于橙(fns)与青(Coyote)交界面上——单独测任何一方都测不出来,这正是本阶段存在的理由。

§4我们做了什么

  1. 综合出 RTL:按仓库官方 make.tcl.in 手工实例化(器件换 VU9P、时钟 4ns、不确定度 27%——后经查证与 Coyote 官方默认逐项一致),csynth 2 分钟通过,139 个 Verilog 文件。
  2. 收齐依赖闭包:Coyote 包装层 12 个 .sv + 队列原语 + RAM 原语;lynxTypes 是 Jinja 模板 → 写渲染器按官方 CMake 默认值实例化(782 行,0 未解析);10 个 Vivado FIFO IP 写行为替身;rocev2_ip 别名模块从端口表机械生成。仿真器定案 xsim(SV interface 重度使用 + 与 Stage D 同工具链)。
  3. 三场硬仗(每场都是一个可复用的诊断手法,细节见 §6 发现):
    • X 污染死锁:SQ 永不放行 → 逐级探针定位到 rdma_flow 指针表 BRAM 读出 X → 仿真侧零初始化(B6);
    • 替身吞包:payload 进了 FIFO 替身就消失 → VCD 时间线锁定 → xsim 不重算引用 SV 队列方法的连续赋值(B7)→ 指针式重写;
    • RETH VA 全零:帧其余 116 字节全对唯 VA 为 0 → 锁存寄存器验尸(SQ 线上数据正确、HLS 解出的 laddr 却是 raddr 的值)→ fns 结构体声明序与 Coyote 打包序互换(B2)→ 修包装层。
    诊断工具箱按序升级:内部 FIFO 空满全扫 → 进程阻塞标志(blk_n)全扫 → 各级进程锁存 meta 寄存器"验尸" → VCD 事件时间线。前两者证明"无阻塞、无滞留",第三者指出事件走到哪一站,第四者给出逐周期剧本。
  4. 四用例全部跑通并回归:write64 → rx_loop → write8k(先按错误假设跑出协议非法帧,进而发现预切分契约 B4,改正后通过)→ rx_neg(坏 CRC 帧被照收,进而发现 RX 检查被禁用 B5)。TB 重构后四用例复跑无回归。
  5. 校验自动化:check_golden_icrc.py(B-4 对拍 + B-5 ICRC 双算)、gen_neg_frame.py(PSN 跳变帧构造 + ICRC 重算)入库,供 Stage C/E 复用。

§5结果怎么看

5.1 B-4/B-5:golden 对拍与 ICRC 双算

[B-4] byte-exact over first 120 bytes: True
[B-4] RTL carries exactly 4 extra bytes: True (rtl=124, csim=120)
[B-5] RTL ICRC bytes : ccbeb072
[B-5] Python ref ICRC: ccbeb072      ← 独立参考实现,零共同血统
[B-5] ICRC match: True

读法:前 120 字节继承 Stage A 的逐字段验证;多出的 4 字节(keep 从 0x00ff… 变 0x0fff…)是 icrc.sv 物化的 ICRC。自洽检查:laddr/raddr 修复前后 VA 从全零变 0x0000334455667788,ICRC 同步从 9caaba4e 变 ccbeb072——两个实现对"VA 参与 CRC"的反应一致。

5.2 B-6:回灌闭环

WR_REQ  vaddr=334455667788 len=64 last=1        ← 放置命令 = RETH 原文
WR_DATA a0 a1 … df(64B,keep 全 1,LAST=1)     ← 放置数据 = 发出的 payload,位精确
F1: 48B opcode=0x11 AETH syndrome=0x1f msn=1    ← 响应方自动回 ACK
[10210us] ACK: opcode=11 pid=17 vfid=0          ← ACK 回灌后请求方 CQE 类比信号

读法:放置 vaddr 与 RETH VA 一字不差、长度 64、数据逐字节等于签名 payload——单 QP WRITE 环回 bit-exact(手册 Stage B 通过标准第一条)。ACK 帧回灌后 m_rdma_ack 携带正确的 pid/vfid,rdma_flow 流控释放。附带确认:m_rdma_ack 的载荷是 32 位 ack_t(last 门控),不是 dack_t(发现 B8)。

5.3 write8k:切分结构

F0: 4156B opcode=0x06(FIRST) psn=0x80ce4e RETH{va=334455667788, rkey=1234abcd, dmalen=4096} icrc=True
F1: 4140B opcode=0x08(LAST)  psn=0x80ce4f 无RETH  payload 从 4096 续,连续性=True icrc=True

读法:长度三角 4156=20+8+12+16+4096+4、4140=20+8+12+4096+4;PSN 连号;RETH 只在 FIRST;两帧 ICRC 均过参考实现。注意 dmalen=4096 是本命令长度而非 IBTA 语义的总消息长度 8192(发现 B4 的第二半)。

§6发现与有效性边界

6.1 九个发现(B1–B9)

B1:2025.2 可综合;PPA 初值到手;Fmax 估计低于目标。
LUT 69,309 / FF 147,050 / BRAM 75 / DSP 0(VU9P 约 5.9% LUT)。HLS 估计关键路径 6.58ns(151.9MHz)低于 250MHz 目标——但 HLS 估计一贯悲观,Coyote 官方就按 4ns 目标发布;裁决权在 Stage D post-route。这行数字就是未来论文资源表的第一行草稿。
B2:laddr/raddr 在包装层与 HLS 之间互换(已修)。
fns@20633d03 的 txMeta 结构体声明序是 raddr 在前、laddr 在后(hpp:227-228),而构造函数参数序相反——csim 走构造函数所以 Stage A 一切正常;Coyote roce_stack.sv 按参数序手工打包,于是 RETH VA 拿到的是 laddr(=0)。表现为"帧其余 116 字节全对、唯 VA 全零"的高迷惑性故障。已在我们的包装层副本修复(STAGE-B FIX 标记)。Stage C 规范:doorbell 打包一律以结构体声明序为准,构造函数参数序不可信。
B3:WRITE 的 payload 是"主动推流",不是请求-响应。
rdma_mux_retrans 对 WRITE 类命令只登记序列 + 发重传缓冲写命令;m_rdma_rd_req 仅在 READ 响应时发出。用户侧(Coyote shell / 我们的 doorbell)必须在提交 WR 后立刻把 payload 推上 s_axis_rdma_rd_req。Coyote 源码注释原话:"Shouldn't it be automatically delivered to the stack?"。Stage C 设计输入:doorbell 提交 WQE 后由控制器同步从 staging 读出并推流。
B4:>PMTU 切分是 SQ 生产者的职责;RETH.DMALen 是本命令长度。
roce_stack 信任 SQ 契约,不切分:直接喂 8KiB WRITE_ONLY 会产出协议非法帧(DMALen=8192 但 payload 4096)。Coyote 在 shell 层 dreq_rdma_parser_wr 切分(req_t.mode 注释为证)。且 FIRST 帧的 DMALen=4096(本命令)而非 IBTA 语义的总长 8192——CX-5 互操作观察项(严格接收方可能报长度错)。Stage C:doorbell 必须内置 FIRST/MIDDLE/LAST 切分器。
B5:本分支 RX 不校验 ICRC——crc_drop 计数器是死的。
crc.hpp:39 无条件 #define DISABLE_CRC_CHECK(与 DBG_IBV/RETRANS_EN 同款分支级硬编码)。实测:payload 损坏、ICRC 失配的帧被照常接受、放置、回 ACK,crc_drop 恒 0。TX 侧 ICRC(SV icrc.sv)真实且已验证。手册"首上板第一眼看 crc_drop"的建议需要加注。环回实验无碍(两端都是自己);接商品 RNIC 时对端会校验我们的 TX(没问题),但我们的 RX 不设防。
B6:仿真-硬件初始化鸿沟:未初始化 BRAM 的 X 会死锁流控。
rdma_flow 的指针表(ram_sp_nc)在 xsim 里读出 X → if(!issued || head!=tail) 永假 → SQ 永不放行。真板上比特流把 BRAM 清零、csim 的 C++ 静态数组也天然是零——只有 RTL 仿真裸奔。修法:对 Coyote RAM 原语 + HLS 生成 RAM 统一 SIM_ZERO_INIT(如实建模比特流,不是作弊)。这也提示:任何"读在写前"的表项依赖上电清零,是移植到非 FPGA 载体时的隐性假设。
B7:xsim 陷阱——引用 SV 队列方法的连续赋值不被重新求值。
assign tvalid = (q.size()>0) 在 always_ff 里 push 后不更新 → FIFO 替身静默吞包,且无任何仿真警告。替身必须写成经典指针式 RTL。凡行为模型进 xsim,此坑通用。
B8:m_rdma_ack 的载荷类型是 ack_t(32b),且只放行 last 拍。
rdma_flow 的 CQ 队列(queue_meta)只搬 32 位 ack 本体、由 data.last 门控入队——TB 最初按 dack_t(33b)解读,导致所有字段整体错 1 位。Stage C 的 CQE 读回寄存器按 ack_t 布局设计。
B9(未决):请求方定时重传在 RTL 窗口内未观测到。
csim 同一激励 20000 次迭代产出 8 份重传副本;RTL 240µs(6 万周期)窗口内 retrans 计数从未跳动。transport_timer 的常数在 csim/综合两分支都只有个位数 tick,理论上应在数µs 级触发——差异未解释。重传数据通路本身已验证(重传缓冲写命令+数据入库正确;NAK 路径正确),未验证的是 timer 触发的自发重发。列为 Stage B 遗留第一项,建议下次直接对 transport_timer 做 VCD。

6.2 本实验证明不了什么(诚实边界)

  • 时序收敛:151.9MHz 是 HLS 估计,不是判决;250MHz 能否收敛要 Stage D post-route。
  • 真实 FIFO IP 行为:10 个 Vivado FIFO IP 用行为替身(深度/延迟不忠实,时钟域转换器被当单时钟);Stage D 换真 IP 后握手时序可能微变,语义结论不受影响。
  • Ethernet 层:帧仍从 IPv4 起,MAC 层在 Corundum 侧(Stage D)。
  • 多 QP / 并发:全部单 QP 单飞;flow-control 的多未完成(N_OST)路径未压测。
  • 吞吐/背压极限:TB 全程 tready=1,无背压场景。

§7结论与对下一阶段的输入

结论:Stage B PASS。协议引擎在 RTL 层被证明与 csim 语义逐字节一致;ICRC 电路与独立参考实现互证;环回放置位精确、ACK/CQE 闭环;违规反应符合 RETRANS_EN=开 的标准语义。包装层与 HLS 之间的三处契约缝隙(B2/B3/B4)全部在仿真里抓获并修复/规范化——这正是 Stage B 存在的意义:这三处若留到板上,全是无波形可看的静默故障。

移交给 Stage C(doorbell L0 + 内存胶水)的具体输入:

  1. SQ 打包规范:以 txMeta 结构体声明序为准(raddr@[119:56] 在 laddr@[183:120] 之前),QPN={vfid,pid},远端地址高 16 位 = {10'b0, strm, dest};qpContext 按三表语义写、避开 0xDEADBEEF/0xFEEDBEEF 魔数(Stage A 发现 5);
  2. payload 推流机:WQE 提交后必须主动从 staging 推 payload(B3),推流长度=命令长度;
  3. 切分器:大 WR 在 doorbell 内切成 FIRST/MIDDLE/LAST,每段 ≤PMTU=4096(B4);
  4. golden 帧库:write64(124B 含 ICRC)+ write8k(两帧)+ 全套 python 工具(对拍/ICRC/坏帧构造)直接复用;
  5. 计数器接线:五计数器仍全部接 AXI-Lite,但文档标注 crc_drop 在本分支恒 0(B5)。

移交给 Stage D:Fmax 估计 151.9MHz vs 250MHz 目标的 post-route 裁决(B1);行为替身换真 axis_data_fifo IP;本报告的资源数作为资源表基线。遗留:timer 自发重传观测(B9)。
